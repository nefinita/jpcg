# 配装搜索：只考虑升级装备 + 全量遍历

## 背景
之前的搜索用「支配剪枝（基础档被升级档逐项支配时删除）」+ 大空间确定性抽样，
属于启发式，不能保证最优。

## 修复
- `jpcg_gear` 的 `build_candidates` 改为按档位收敛：
  - `allow_upgraded = true` 且**没有上限约束**时，每个槽位只保留**升级档**（没有升级档的槽位回退到全部候选）；
  - 存在上限约束时保留全部档位——上限可能只有基础档能满足（保留 `upper_bounds_keep_feasible_base_tiers_*` 行为）；
  - 移除旧的支配剪枝与 `stats_ge`/`template_total`。
- 升级档空间（莫问 2 件/槽位 → 2^12 = **4096**）小于预算时走全量遍历，`complete = true`。
- 前端 `max_combinations` 由 100000 提到 **1_000_000**（引擎上限），保证升级档空间全量遍历，不再抽样。

## 验证
- 新增 `allow_upgraded_searches_upgraded_tiers_only`：串行/并行搜索的最优配装全部为升级档，且 `complete = true`。
- `cargo test --workspace` / `cargo fmt --check` 全绿；前端 tsc + 157 项 vitest + build 通过。
