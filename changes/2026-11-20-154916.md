# 多职业数据目录、后端职责与连招界面通用化

## 修改

- 正式运行数据改为 `data/<profession>/{shuxing.toml,combat.toml,gear/}`，共享值集仍位于 `data/values/`，结构模板集中于 `data/_template/`。旧 `data/{shuxing,combat,gear}/` 仅保留读取兼容，新布局优先，技能编辑只写新布局；`_template` 不参与职业扫描。
- 数据根解析统一覆盖开发目录、环境变量、安装版用户目录与 bundle Resources。Tauri 打包按新目录收录各职业技能、时序、配装和共享值集，产物继续由 `cargo tauri build` 写入 `target/release/bundle/`。
- 默认配装、重置及真实目录旧配装的属性规则修复统一收口到 Rust `jpcg_gear::host::prepare_loadout`，static／dynamic 共用后端入口；前端不再复制默认配装或职业换算规则。
- 自动调优停止按钮补齐与界面一致的样式和停止图标，保留原取消语义；用户已实机确认显示正常。
- 连招页保留「器形」，并将莫问专属的「曲风」界面术语改为通用「形态」。器形名称与技能过滤读取 `[[form]]`，形态显示名读取 `[meta].qifeng_names`，秘籍槽数、混选槽位和上限读取 `[meta]` 规则。
- `CombatMeta`／`CombatMetaDTO` 增加形态名称表和面板规则的双向转换。莫问与模板显式填写规则；后端默认值只用于旧文件兼容，前端不再写死 `qin/jian/yangchun`、4 个秘籍槽或「9 选 3」。
- 同步数据维护指南与 M5 计划：本次只完成界面和数据契约通用化，内部 qifeng 字段、点数上限、事件及钩子的结算模型未改，不能据此宣称全门派资源引擎已泛化。

## 数据边界

- 当前仓库仍只有 `mowen/` 一份真实职业数据；非莫问语义仅使用前端 mock 与 Rust DTO 测试验证，不伪造第二职业数值。
- 保留用户现有 `data/values/index.toml` 清单与默认选择，未把未登记快照冒充界面可选值集。
