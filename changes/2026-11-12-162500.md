# 修复：计算结束标记会把同 GCD 的下一招算进窗口

## 问题
「计算结束」flag 吸附到**下一个施放的起手**，而下一招的命中时刻通常也等于这个起手时刻；
击杀率 / 总伤的窗口过滤是 `t <= kill_end`（闭区间），于是结束标记下方的那一招（同一时刻）被算进了窗口，
表现为「在计算结束下方加一个羽，击杀率反而变高」。

## 修复
- `crates/jpcg_combo/src/timeline.rs`：结束 flag 吸附时用 `start - 1e-3`（起手前 1ms）作为窗口终点，
  下一招命中（= start）不再落入窗口；放在序列末尾、无下一招时仍用最后一个动作结束时刻（包含最后一招）。
- 新增回归 `end_flag_excludes_cast_at_same_time`：cast / 结束 / cast 时，总伤只有第一招，目标打不死。

## 验证
- `cargo test --workspace` / `cargo fmt --check` 全绿；前端 157 项 vitest + build 通过。
