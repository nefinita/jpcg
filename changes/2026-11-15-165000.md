# 调优使用固定击杀范围（所有候选同一绝对时间段）

## 问题
调优按每个候选自己的 flag 窗口评估：攻速越高，序列越快、窗口越短，窗口内 DOT 跳数变少 →
加速被系统性低估（实测：御劲手窗口 3.0–10.5s 共 7.5s，加速手 2.875–10.0625s 共 7.19s，加速手反而少伤害）。

## 修复
- `TimelineRequestDTO` 新增 `fixed_window: Option<[f32; 2]>`；`TimelineInput.fixed_window` 提供时
  直接作为击杀窗口（覆盖 flag 推导），总伤/击杀率/DOT 时间窗都按这个固定时间段统计。
- `jpcg_gear::prepare_request`：时间轴目标先按**基准（当前）配装**跑一次，取 `kill_start/kill_end`
  写进 `fixed_window`；之后所有候选共用同一绝对时间段——「划定的击杀范围」。
- 排轴器/驾驶台不受影响（不传 fixed_window，仍按实际 flag 窗口）。

## 验证
- 新增单测 `fixed_window_counts_dot_ticks_beyond_flag_window`：固定窗口能统计 flag 窗口外的 DOT 跳。
- `cargo test --workspace` / `cargo fmt --check` 全绿；前端 tsc + 157 项 vitest + build 通过。
