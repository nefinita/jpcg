# 修复配装默认属性规则与 Tauri release 打包

## 问题与原因

- 新建配装默认填写了五维基础值，却没有写入 `attribute_rules`；真实装备也包含五维与额外气血，因此默认状态必然触发“旧模式不能忽略这些输入”。随附 `sample-loadout.toml` 也存在同样矛盾。
- `make build-static` / `make build-dynamic` 绕过 Tauri CLI 直接执行 `cargo build`，没有形成完整的应用打包流程，且默认产物落在 `target/debug/`。
- Tauri `bundle.resources` 缺少配装目录加载必需的 `enchants.toml` 与 `wucai.toml`，安装版需要手工补数据。

## 修改

- 新建配装默认显式使用 `attribute_rules="profession-toml"`；真实装备目录加载时修复旧版本遗留的无规则配装。合成样例及历史规则 ID 不做隐式迁移，后端仍拒绝旧模式静默丢弃五维／额外气血。
- 随附配装样例显式选择职业 TOML 规则，CLI 与动态桥接不再依赖调用方补字段。
- 两个应用构建目标统一改为 `cargo tauri build`，执行前端 `beforeBuildCommand` 并生成平台 app／安装包；保留 static／dynamic 特性区分。
- `BUILD` 默认改为 `release`，默认产物位于 `target/release/` 与 `target/release/bundle/`；显式 `BUILD=debug` 才使用调试目录。
- 动态桥接测试按当前测试 profile 查找动态库，避免 release 测试仍写死 `target/debug`。
- 打包资源补齐 `data/gear/enchants.toml`、`data/gear/wucai.toml`；README、属性引擎说明及 Makefile 顺序守卫同步更新。
