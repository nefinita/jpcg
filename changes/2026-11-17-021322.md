# 联合穷举：在面板合成前按四件套和加速约束剪枝

## 问题与修改

- 原 `optimize_joint` 对装备 × 附魔 × 五彩石的每个叶子解码、合成完整面板后才检查约束；GPU/AVX-512 只加速后面的 MC，无法消除这些无效候选的 CPU 开销。
- 新增轻量、流式的 `JointSearch`：优先选择套装防具，预计算各后缀的套装最大可达件数与加速范围。无法满足必选套装、跨来源 2+2 限制或加速上下界时直接跳过整个分支。其余属性约束仍由正式面板合成器复核。
- 加速范围包含裸装、装备、固定镶嵌、附魔、五彩石和套装奖励；混档奖励按各阈值的升级件数分别判断。装备轴与装饰轴遵循原有不同方向的混合进制解码，重新排序遍历不会改变具体配装。
- CPU 和 wgpu 共用筛选后的候选批次，不预扫描完整空间；`visited` 包含已证明无解的分支叶子数，`evaluated` 记录实际评分，取消时不报告完整搜索。原有有界入口及预算语义保持不变。
- 补齐单候选附魔的必装行为，同分时不再把缺少必选装饰的基线作为搜索结果；基线仍保留用于比较。未指定随机种子时，联合搜索固定为 0，保证基线与批量 MC 使用相同样本。

## 验证与边界

- 原始穷举逐项对拍：混档、各部位不同加速、套装奖励、镶嵌、装饰、加速上下界、不可达约束、流式分批和取消；另覆盖数十亿以上理论叶子的整支跳过。
- 本机 M4 Max：Metal 与 CPU 的 50,000 样本击杀计数一致，完整配装搜索与 CPU/原始穷举评分一致；gear/combo/compute 回归（含桌面动态桥接）、clippy、格式检查及 gear model-only 检查通过。clippy 仍有原有警告。
- 在用户要求暂停 ws 前，9970X 的 AVX-512/标量对拍，以及两张 R9700 Vulkan 的 50,000 样本内核与完整配装搜索对拍已通过；附加 RX 7900 GRE 也通过。ws 采用 `/tmp/jpcg-gpu.IwmwP6` 隔离源码，未修改原工作区；后续 ws 测试暂停，等待用户通知。
- release 合成样例的候选准备基准：1,048,576 个原始组合，仅 23,808 个进入完整合成；M4 Max 单次旧路径 2,207.471 ms，新路径 56.293 ms，约 39.21 倍。基准含完整候选集合一致性断言，可用 `cargo test -p jpcg_gear --release --lib joint_prefilter_benchmark -- --ignored --nocapture` 重现。
- 上述耗时仅代表候选准备/硬约束筛选，不含时间轴和 MC，不代表实际完整配装的端到端加速倍数。仍可行的大量候选需要计算。
