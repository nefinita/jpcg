# 本机真实配置的全量约束筛选基准

- 从本机开发版 WebKit localStorage 只读取得用户确认的莫问存档：live-50、竞技场四件套、加速至少 928、三来源升级装备、每槽必选附魔/五彩石。测试请求快照保存在 `/tmp/jpcg-current-request.json`，不修改本地存档。
- 抽出 `joint_space`，使生产联合搜索和基准共用装备/装饰候选定义。新增显式忽略的 `full_current_config_filter` 基准：逐批实际遍历生产筛选器产出的全部合格叶子，不运行时间轴或 MC；每批首尾通过正式合成器复核。
- 独立计数使用装饰加速整数分布 DP，并对全部 4,096 种装备调用正式合成器检查套装与加速。该计数仅用于核对，不替代实际筛选器遍历。
- M4 Max release 单次测试结果：原始 3,185,049,600 组合，768 种装备满足套装要求；最终 395,020,800 个组合合格，剪掉 2,790,028,800 个（87.60%），完整筛选约 29.8 秒，24,112 个首尾样本合成复核全部通过。生产筛选总数与独立计数完全一致，visited 等于完整空间。
- 结果保存在 `/tmp/jpcg-current-filter-result.json`，详细日志 `/tmp/jpcg-current-filter.log`。复现方式：设置 `JPCG_DATA_DIR` 为实际数据绝对路径、`JPCG_FILTER_REQUEST` 为请求快照路径，运行 `cargo test -p jpcg_gear --release --lib full_current_config_filter -- --ignored --nocapture`；可用 `JPCG_FILTER_REPORT` 指定报告路径。
- 这里测量的是 CPU 提前筛选（含每批首尾合成复核），不包含所有合格组合的完整合成、时间轴或 Metal MC，不能当作完整自动调优耗时。仍有近四亿合法组合需要后续处理。ws 未连接或运行测试。
