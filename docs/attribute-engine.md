# 装备属性换算引擎（#98）

按 Qin 的需求，**当前游戏版本为50级，各职业换算表随对应职业 TOML 读取**。先打通原始装备属性→玩家面板→现有计算引擎，再由维护者填写各职业的真实系数、用游戏面板验证。引擎不根据等级或职业名称猜系数。

此前的四心法130级硬编码已从生产代码移除；历史ID不能继续计算，前端也禁止复用其缓存结果。旧手填及未启用转换的配装继续走旧公式。尚未验证的系数不伪装成正式50级数据：现有 `data/shuxing` 中的130级技能文件、`data/gear` 的 `synthetic-v1` 装备库均未冒充迁移完成。

## 配置与录入流程

在 `data/shuxing/{职业ID}.toml` 增加 `[attributes]`，与该职业技能共用文件和读取优先级。参考 [可解析的录入结构示例](examples/profession-attributes-50.toml)：**示例全部系数人为构造，只用于测试，不是游戏数值**。

- `id`：该职业换算表的版本标识；`level`：该表等级；`value_set`：显式匹配的等级常数集；`source`：可核查来源或待核验说明。
- `main_stat`：`liliang/shenfa/gengu/yuanqi`；`damage_kind`：`physical/solar/lunar/neutral/poison`。
- `qixue_multiplier`：基础气血阶段总乘数，分子／分母必须显式填写；例如无该阶段增益时明确填写1/1。引擎不预设心法气血加成。
- `[[attributes.conversions]]`：`from` 为五维之一（包括`tizhi`），`to` 为 `gongji_base/gongji_extra/huixin/pofang/qixue_base/qixue_additional`，`numerator/denominator` 为非负整数比例。分母必须正数。每一条单独截断，可录入同一属性到同一目标的多个独立转换阶段。
- 不存在某种转换时由维护者明确不列该项；`conversions=[]` 表达所有转换为零。缺少整个表或必需字段时拒绝执行，不能以缺失代替已经确认的零系数。

读取校验：职业ID须安全、最高优先级文件不可损坏、同文件 `[version].level` 必须等于 `[attributes].level`；所选数值集必须真实可用且等级、ID一致，禁止以兜底50级常数混算130级规则。职业主属性、内外功类型须与配装目录匹配。未知字段和非法枚举报错，避免手填拼写被忽略。

当前仓库默认值集 `cszj-exp-260908` 已标为50级；其名称仍是历史“体验服·苍生铸世一测”，这不证明常数已适用今天版本。职业技能文件多数仍标130级。不能只改一个等级标签冒充当前真实数据：需维护者同时确认该职业技能、换算表、数值集及装备数据版本，再选择匹配配置。任何职业都能录入，无四职业白名单。

在配装界面显式选择“从职业 TOML 读取换算规则”，保存的选择值为 `attribute_rules="profession-toml"`。导入／导出保存原始输入和选择；每次合成重新读取职业文件，手动改系数无需重编译：编辑文件后点击“重新读取职业规则”。职业TOML模式在新会话及显式重读后必须重新合成，成功前旧缓存不能驱动后续伤害／连招。技能编辑器的加载／保存保留同文件的换算表，旧编辑请求不认识该字段也不会擦除它。

## 输入与计算阶段

`Stats` 的 `tizhi/liliang/shenfa/gengu/yuanqi/qixue_additional` 缺失为0。`zhushuxing` 是主属性**增量别名**，先加到对应具名属性；同一来源不可两栏重复填写。

`base`、装备模板和套装字段均是**主属性及心法转换前的原始点数**，不是已经转换的最终裸装面板。系统不自动补入等级／心法固有属性。

计算顺序：

1. 原始裸装点数 + 12件装备 + 已激活套装，逐字段检查溢出。
2. 将主属性别名加到职业配置的具名主属性。
3. 对每条转换计算 `floor(五维点数 × numerator / denominator)`，分别加到目标阶段；不合并系数，不把一次转换结果作为另一条的输入。
4. 基础气血阶段乘 `qixue_multiplier` 并截断，之后加额外气血阶段。
5. 基础攻击与心法额外攻击分开传给 core；派生会心、破防及加速完整传递。

乘法使用u64中间量，原始求和和最终面板越过u32时返回错误。所有非负整数比例均由文件提供，Rust没有通用基础属性转换常数。示例根骨1的两条会心比例9/10与2/5，分别截断得到0，而非合并后得到1。

`Composed.stats` 保存原始合计，`panel` 保存结果、职业规则ID、等级、值集和来源；`verified_in_game` 始终为false。不能把 `panel` 再作为 `base` 输入。配装约束和生存Pareto使用派生气血／攻击／会心／破防／归一主属性。一次优化固定读取到的同一规则，避免搜索途中文件编辑使候选口径漂移。

## 现有计算器接入与兼容

- `jpcg_gear::player()` 是唯一适配器。新增 `PlayerConfigDTO.zhuanhua_gongji:Option<u32>`：`Some`（包括0）代表心法额外攻击已换算，禁止 core 再使用旧 `atk_up` 转换主属性；`None` 保留旧f32公式和金标准。
- 新路径基础攻击增益为 `floor(基础攻击 × (1+base_atk_pct/100)) + 心法额外攻击`；武器伤害仍独立计算。该增益为现有接口百分数，未宣称完整战斗增益叠加规则已经复刻。
- 单技能、连招、时间轴、配置保存加载保留转换标记及加速。玩家气血不会覆盖敌人的 `target_hp/max_hp/current_hp`。
- 携带转换标记的host求导报错，要求修改原始配装后重新合成。直接Rust偏导只针对固定DTO，主属性偏导0不代表真实配装收益0。
- 旧手填编辑器拒绝加载已经转换的面板快照，提示导入原始配装TOML，避免编辑主属性却保留过期结果。
- C ABI仍为1，新core/combo通过 `player_attribute_capabilities` 声明 `converted_attack_v1`。桌面动态桥接在转换请求、导入及存档读写前验证能力；旧模块不支持便报错。外部FFI调用方也必须探测能力。
- 未选规则却输入非零五维／额外气血时拒绝计算，避免旧链路静默丢弃。历史130级ID不自动迁移为当前职业规则，需明确重选。

## 测试与证据边界

`crates/jpcg_gear/tests/attributes.rs` 使用人为50级系数测试四类主属性、独立截断、主属性别名、额外气血、版本／分母／溢出拒绝，并在隔离进程里执行真实职业TOML读取、配装合成、优化、core伤害和导入导出。只改职业TOML会改变下一次结果；缺表、混用50/130级必须失败。

`scripts/test-attributes-dynamic.py` 默认用临时合成50级职业文件验证实际动态库，不修改正式数据。可选 `--reference-dir <可信checkout> --samples 10000` 将固定的历史130级社区模型写入临时职业表，与Rust执行结果差分；历史测试仅证明数据驱动引擎可重现该模型，**不是当前50级职业校准**。

历史参考固定为 [IcyTide/Generator 21f472e](https://github.com/IcyTide/Generator/tree/21f472e211581ac1c1a7fa5ea2ff9199df6151cb)。未发现其许可证，因此不复制代码、不批量分发其数据，脚本从用户提供的本地checkout临时读取必要事实。原版本四心法40,000组零差异是历史实现的记录，不能替代本次数据驱动版本的验证，更不能替代游戏实测。

待完成：真实50级职业系数及游戏面板前后基准、真实装备／套装值、强化／镶嵌／附魔／特效、完整防御／招架转换和战斗增益。当前六个目标阶段不覆盖全部人物属性。core高增益攻击仍会饱和到u32，极端伤害累加及会心超过100%等既有行为未纳入“完全复刻”保证。#98保持开放。
